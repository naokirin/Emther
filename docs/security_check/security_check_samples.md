検知システムの評価に使いやすいように、**実際の社内議事録・Slack文字起こし・業務メモに近い自然な文章**にしつつ、セットごとに検知対象を変えます。

また、実データではなく、**すべて架空の人物名・会社名・連絡先・金額等**にしています。
「検知されるべき情報」は、できるだけ **何を検知すれば正解なのか** が分かるようにしています。

## 評価用としては、この10セットをさらに3段階に分けると使いやすいです

今回の目的が「外部LLMに送る前に、軽量なモデルで個人情報・機密情報をマスキングする」用途であれば、単に10種類の文章を作るより、**検知難易度を分ける**のがおすすめです。

| 難易度 | 例                          | 期待する検知     |
| --- | -------------------------- | ---------- |
| ★☆☆ | `山田太郎`、`090-1234-5678`     | ほぼ100%検知   |
| ★★☆ | 「顧客担当の山田さん」「本番環境の認証情報」     | 文脈から検知     |
| ★★★ | 「来月発表予定の新料金」「取締役会未承認の投資計画」 | 機密性を文脈から判断 |

特に**セット6・7・10**あたりは、今回作ろうとしているシステムの性能を見るのにかなり重要だと思います。

また、実装を評価するなら「検知された／されなかった」だけでなく、各テキストについて

```text
PERSON_NAME
EMAIL
PHONE
ADDRESS
CUSTOMER_INFO
AUTH_CREDENTIAL
FINANCIAL
HR_CONFIDENTIAL
BUSINESS_CONFIDENTIAL
SYSTEM_CONFIDENTIAL
```

のような**情報種別まで正しく分類できるか**を見ると、後でLLMへのマスキング処理につなげやすくなります。
