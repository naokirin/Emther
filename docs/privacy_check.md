## 0. 目的

大きめのテキストや自分で書いていないテキストを、Journal／相談／Observation Dump などに投入する前に、次を**ローカルだけで**事前確認できるようにする。

- 登録済み人名がどう `PERSON_n` に置換されるか
- 個人情報・機密情報っぽい箇所の候補リスト

安心のためのオプトイン検証ツールであり、日常の短い入力を止めない。

### 2.1 評価に基づく優先度（2026-09-13 合意）

成功定義は帯で分ける。ルール本線を肥大化させない。

| 帯 | 対象 | 期待 |
|---|---|---|
| **A（確実に強める）** | メール・電話・**住所・生年月日・ID系**・**企業名**・敬称付き人名の正しさ | 第1段ルールで高い再現＋**人名は FP 抑制優先** |
| **B（段階的）** | 認証・秘密の**言及**（短い核） | CORE 維持。長い言い回しの積み上げはしない |
| **C（目視＋AI参考）** | 未公開日程・料金・財務・人事文脈など | **検知できればよいが必須达标にしない**。第2段 AI は参考。空振り時はルール結果を主にする |

補足:

- 否定文脈（「給与は含まれていません」）は当面気にしない。UI の認知コストが問題になったら上げる
- 敬称なしダミー人名の全検出はゴールにしない（FP 抑制と両立しにくい）
- カテゴリ細分化（FINANCIAL / HR 等）は自動マスク設計と同時期でよい

実装順: **P0 人名信頼性 → P1 企業名→住所/DOB→ID → P2 AI参考の明示**

## 3. コード構成（コアとチューニングの分離）

| ファイル | 役割 |
|---|---|
| `mask-check.ts` | エンジン（実値 regex、敬称／話者、ハイライト、AI オーケストレーション） |
| `mask-check-types.ts` | 共有型 |
| `mask-check-lexicon.ts` | **CORE**（短い核フレーズ・最小 stopword）と **TUNING**（人名除外・lookahead 等。機微キーワードは縮小済みで空） |

TUNING の機微キーワード羅列は過適合のため縮小した（人名まわりの辞書は残置）。業界定石との対応は `docs/privacy_check_research.md`。

### 第1段 `phase: "quick"`

- `previewNameMask`
- 人名候補（敬称・話者・ひらがな文脈・**Kuromoji 人名 POS**）
- 実値（メール・電話・鍵・**住所・生年月日・ID・企業名**）+ CORE キーワード
- `match` / `start` / `end` / `highlights`

### 第2段 `phase: "ai"`

- ローカル SLM の追加機微候補（**未公開・社外秘っぽい文脈は参考扱い**）
- 人名候補の一般語除外フィルタ
- `aiWeak` 時はルール結果を主に参照

### UI

- 検出ハイライト（原文）
- マスク後テキスト（コピー用）
- 文脈機密は完全検知ではない旨を disclaimer / AI 注記で示す
