# Dashboard UI 可読性・見た目の改善ポイント

作成日: 2026-09-07  
対象: Dashboard（`/`）を中心とした「なんとも言えない読みにくさ」の整理  
関連: `docs/em_human_story_and_ux.md` / `docs/improvement_v1.md` / `web/src/app/page.tsx` / `web/src/app/page.module.css`

---

## 0. この文書の位置づけ

`em_human_story_and_ux.md` は **人間EMの物語・判断キュー・ナビの迷子** を扱う。  
本ドキュメントは、それと重なりつつも別軸の **視覚階層・タイポ・コピー密度・装飾の競合** を扱う。

| 軸 | 主文書 | 問い |
|---|---|---|
| 情報設計・ストーリー | `em_human_story_and_ux.md`（P0〜P1） | 今日向き合う組織の問いは何か？ Runの消化係になっていないか？ |
| 見た目・可読性 | **本ドキュメント** | 視線の置き場は一目で分かるか？ 読む順番がレイアウトから伝わるか？ |

**結論（関係性）:**

- ストーリー文書の **P0-5**（先頭を「今日の組織の問い」1文＋判断3件に圧縮）を進めると、読みにくさの **主因（情報過多・主問の不在）** は大きく改善する。
- ただし **パネルの見た目均一・フォント階層の狭さ・長い説明文・日英混在見出し・1行内の装飾過多** は、P0を進めても自動では消えない。**別途のUI作業が必要。**
- **P1-10**（戦略・人物・進行中介入を朝に載せる）を **P0-5 なし**で先にやると、行が増えて可読性が悪化しうる。順序はストーリー文書 §7 に従う。

## 1. 課題の診断（なぜ読みにくいか）

単一のバグではなく、次が重なっている。

### 1.1 情報設計（ストーリー文書と共通）

1. **情報過多で「最初の一文」がない**  
   初回セットアップ → 時間帯バナー → 次にすべきこと → Fleet → Activity → Vitals → Journal＋長期プロファイル → Inbox が縦積み。朝の主問（今日向き合う組織課題）が視覚的に固定されていない。
2. **同じシグナルの多重表示**  
   異常・Yield・Vitalsなどが「次にすべきこと」／Fleet／Activity／Inbox に重複し、読んでも前に進まない感覚になる。
3. **ナビ過多（約10タブ）**  
   Dashboardに入る前から認知負荷が高い（ストーリー文書 P1-6 / (9)）。

### 1.2 見た目・可読性（本ドキュメント固有）

4. **視覚階層がほぼフラット**  
   ほぼすべてが同じ `.panel`（白背景・同枠線・同角丸）。見出しも一律 `h2 { font-size: 14px }`。主役と副次が区別できない。
5. **フォント階層が狭い**  
   見出し14px、本文・説明13px、リスト行・バッジ11〜12px、Activity 11px monospace。全部が同じ濃さに感じる。
6. **説明文が毎パネル長い**  
   設計意図の subtitle（「判断待ち・エラー・未整理のIssue…」「Qwen2.5-0.5B…」等）が行動の前に立ち、muted の灰色テキストの海になる。
7. **見出しの日英・実装語混在**  
   例: `Quick Journal (Hybrid Data Ingestion)`、`Agent Activity Stream`、`Inbox（タスクを起票 / 稼働中のエージェント）`。箱の意味取得にワンテンポかかる。
8. **1行内の装飾過多**  
   絵文字 + kindLabel バッジ + 本文（＋ Inbox では StatusBadge・相談メタ）が同時に並び、文としてのスキャンより装飾の識別が先に来る。
9. **色が常時オン**  
   Fleet・Vitals・「次にすべきこと」が同時に緑／黄／赤／破線ストライプ。色の仕事（「今ここ」）が相対的に埋もれる。
10. **Activity Stream の可読性トレードオフ**  
    11px・等幅・固定高・省略表示は「端末ログ風」として意図的だが、周囲のカードUIとのトーン差が大きく、視線切替コストが高い。

## 3. UI改善ポイント（提案リスト）

実装変更の提案。ストーリー文書の P0 と **並行または直後** に効くものを U 系 ID で区別する。

### U0：P0-5 とセットでやる（情報圧縮の見た目側）

ストーリー文書 **P0-5** を実装するときの UI 約束。新画面は増やさない。

| # | 改善 | 狙い |
|---|---|---|
| **U0-1** | 先頭ブロックだけ視覚的に「主」にする（余白・見出しサイズ・背景差のいずれか）。それ以外のパネルは一段下げる（折りたたみ／デフォルト折り／副次ラベル） | 視線の最初の着地をトリアージに固定 |
| **U0-2** | Fleet / Activity を「副次」扱いにする（折りたたみ、またはコンパクト1行化）。常時フル表示しない | 多重表示ノイズを減らす |
| **U0-3** | 「次にすべきこと」以外の長い subtitle を削る／初回のみ／ツールチップへ退避 | 行動の前の灰色テキストを減らす |

### U1：タイポと階層（P0 後でも単独で効く）

| # | 改善 | 狙い |
|---|---|---|
| **U1-1** | 画面内の文字サイズ帯を広げる。例: 主見出し 18〜20px、パネル見出し 15〜16px、本文 14px、メタ 12px。11px はログ等の例外に限る | 「全部同じ大きさ」感を解消 |
| **U1-2** | パネル間の余白・見出し下マージンを揃えて「セクション＝呼吸」を作る。密なリストはリスト内だけ密でよい | Timeline の S 改善と同様、ブロック単位で読めるようにする |
| **U1-3** | 主エリアと副次エリアで背景／枠の強さを変える（全部同じ白カードにしない） | フラット感の解消 |

### U2：コピーとラベル

| # | 改善 | 狙い |
|---|---|---|
| **U2-1** | パネル見出しを **日本語の役割1語（＋必要なら短い補足）** に揃える。実装語（Hybrid Data Ingestion 等）は見出しから外す | 箱の意味取得を即時にする |
| **U2-2** | 例候補: 「次にすべきこと」「エージェントの状態」「直近の動き」「チームの状態」「メモする」「相談・起動」 | 日英混在の認知コストを下げる |
| **U2-3** | バナー・subtitle の文量上限を決める（例: 1行40字前後、2行まで）。超える説明は Settings／ヘルプ側へ | 日常利用のノイズ削減 |

### U3：リスト行・バッジ・色

| # | 改善 | 狙い |
|---|---|---|
| **U3-1** | 「次にすべきこと」行を **種別（レーン or 1ラベル）＋本文** の2層に。絵文字とバッジの両立をやめる（どちらか一方） | 1行スキャンを文として成立させる |
| **U3-2** | Inbox 行も同様に、メタ（状態・種別）を本文から視覚分離（2行目をメタ専用など） | 装飾競合の解消 |
| **U3-3** | 色塗りの既定を弱める。例: 平常時は枠・左アクセントのみ。全面 tint は urgent のみ | 緊急度のコントラストを戻す |
| **U3-4** | 破線ストライプ（stale / 評価不能）は残してよいが、同時に画面上に多数出ないよう「次にすべきこと」側に寄せる | 不明状態の言語は維持しつつ散乱を防ぐ |

### U4：個別ブロック

| # | 改善 | 狙い |
|---|---|---|
| **U4-1** | Quick Journal と長期プロファイルを視覚的に分離（見出し階層 or 折りたたみ）。同一パネル内の「入力が2種類」感を減らす | 日中の主行動（メモ）を明確化 |
| **U4-2** | Activity Stream はフォントを本文に近づけるか、折りたたみ時のみ mono 密表示にする | ログ風とカードUIの落差を緩和 |
| **U4-3** | 2カラム（Journal / Inbox）は狭幅で折り返しが増えるため、主問圧縮後は「片方を下へ」または「片方を別画面誘導強化」を検討 | 半幅での読みにくさ対策 |
| **U4-4** | セットアップバナーと時間帯バナーが同時表示のとき、片方を短文化 or 統合しない（役割は別のまま、高さだけ抑える） | 先頭の二重バナー圧の緩和 |

## 4. ストーリー文書との対応表

| 読みにくさ要因 | 主に効く手段 | 備考 |
|---|---|---|
| 主問がない・情報過多 | ストーリー **P0-5** ＋ **U0-*** | 両方必要。P0-5 だけだと見た目はまだフラットなまま残りうる |
| オペキュー混在・多重表示 | ストーリー **P0-1, P0-4** ＋ **U0-2, U3-4** | レーン分けは構造、折りたたみ・色は見た目 |
| ナビ迷子 | ストーリー **P1-6, P1-11** | UI文書の範囲外（ナビ側） |
| フォント・パネル均一 | **U1-*** | ストーリー文書には未記載 |
| 長い説明文・日英見出し | **U2-*** | 同上 |
| バッジ／絵文字／色の競合 | **U3-*** | 同上 |
| Journal＋プロファイル同居など | **U4-*** | 同上 |

## 5. 進め方の提案

1. **ストーリー P0-5 と U0 をセットで**（Dashboard 先頭の圧縮＋主／副の見た目差）。新画面は増やさない。
2. **U2（見出し語彙・説明文削減）** はコストが低く、単独でも即効性がある。
3. **U1（タイポ・余白）** はグローバルに効くため、Dashboard で試してから他画面へ波及。
4. **U3 / U4** は P0-1（レーン）の実装と干渉しうるので、レーン構造が固まってから行レイアウトを整えると手戻りが少ない。
5. 判断基準はストーリー文書と同じ問いに、次を足す。

> この変更は、人間EMの視線を最初の3秒で「今日の判断」に着地させるか？  
> 装飾や説明を減らしても、種別・緊急度はまだ分かるか？

---

## 6. やらないこと（この文書の範囲外）

- 新画面の追加やタブ増（迷子を増やす）
- ストーリー文書 P2（NER・マスキング等）の代替
- デザインシステムの全面刷新やブランドトーンの作り直し（既存の CSS 変数・パネル言語を壊さない範囲で階層だけ足す）
