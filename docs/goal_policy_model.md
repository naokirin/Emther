# Emther: Goal / Policy / Theme 方針

## 目的

Emtherにおける「組織方針・目標」の扱いを、単なるMVV / OKRの入力・管理ではなく、**EMが自分のチームについて考え、判断するための前提・レンズ**として設計する。

Emtherは「正しい目標管理手法を適用させるシステム」ではなく、EMが

* どこを目指しているか
* 何を大切にしているか
* 今何に意識を向けているか

を自然な形で記録し、それを日々の観測やAIによる分析につなげるシステムとする。

## 方針

### 1. MVVは残す

MVVは、組織として長期的に大切にする価値観・方向性として扱う。

* 比較的安定した情報
* Goalそのものではない
* 日々の判断における長期的な背景・価値観

### 2. Goal / Policy / ThemeをEmtherの基本的な方針単位とする

#### Goal

EMとして見据えている「到達したい状態」。

* 遠いGoal / 中間Goal / 近いGoalなど、異なる時間軸を持ってよい
* SMARTな目標であることは望ましいが、必須条件にはしない
* 定量目標でなくてもよい
* 「まずこういう状態を目指したい」という段階から登録できる
* 状況や学びに応じて更新・変更できる
* Goal同士の上下関係は多対多で紐づけられる（`parentGoalIds`）。チームの階層（名前の `/` パス）とは独立であり、上位チームのどの Goal と下位チームのどの Goal が結びつくかは自明ではないため、自動連動はしない
* 概要スキャンでは Goal をルート列＋子ネストの階層で示し、Theme は件数のみ。紐づく Theme 本体は Goal フォーカス時に表示する（共有子は親列ごとに重複し「共有」と明示）

#### Policy

Goalに向かう際に守りたい判断原則。

* 大切にすること
* 優先すること
* やらないこと
* 判断に迷ったときの原則

などを記録する。

#### Theme

現在、EMとして特に意識・注力している領域。

* 一定期間の重点テーマ
* 必ずしも明確なGoalやKPIを持たなくてよい
* 「今はここを見る」という意識の向きを表現する

### 3. OKRを必須の構造にはしない

OKRは重要な手法の一つだが、Emtherの基本構造として必須にはしない。

**OKRを使いたい場合は、Goalを具体化・管理する方法としてOKRを利用できる。**

一方で、

* OKRを使わない
* 定性的なGoalを置く
* Milestoneで管理する
* 別の方法でGoalを具体化する

といった使い方も同じように許容する。

つまり、

> OKRを入力するためにGoalを作る

のではなく、

> Goalを考え、必要であればその管理方法としてOKRを使う

という関係にする。

### 4. 「入力項目を埋めること」を目的にしない

Goal / Policy / Themeについても、すべてを必須入力にはしない。

EMがまだ明確に言語化できていない場合も許容する。

例えば、

> 「チームの自律性を高めたい」

という曖昧なGoalから始めてもよい。

日々のJournal、Issue、振り返り、AIとの対話などを通じて、徐々に具体化されていくことを想定する。

## 達成したいこと

### 1. EMの「考えていること」を自然に記録できる

会社のOKRや半期区切りに合わせるのではなく、EM自身にとって適切な時間軸・粒度でGoalを設定できるようにする。

### 2. 方針を「AIが観測するためのレンズ」にする

AIがJournalやIssueなどを分析するとき、

* 現在のGoal
* Policy
* Theme
* MVV

を文脈として利用できるようにする。

単純な「OKRの進捗確認」ではなく、

> 「現在の方針から見て、最近何が起きているのか？」

をAIが考えられる状態を目指す。

### 3. Goal自体も更新対象にする

現実を観測した結果、

> 「そもそも今のGoalが適切なのか？」

をEMが考えられるようにする。

Goal / Policy / Themeは固定された正解ではなく、EMが現実から学びながら更新していくものとする。

### 4. EMの思考をOKRに閉じ込めない

Emtherでは、OKRを尊重しつつも、EMの思考をOKRの構造に無理に当てはめない。

**MVV → Goal / Policy / Theme → 日々の観測・判断**

という緩やかな構造を基本とし、必要に応じてその中にOKRなどの具体的な管理手法を持ち込める設計を目指す。

## 設計思想

> **Emtherは「目標を管理する場所」ではなく、EMが「どこへ向かい、何を大切にし、今何を見るのか」を考え続ける場所。**

Goal / Policy / Themeは、そのための最小限の共通言語とする。
