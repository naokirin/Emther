# Emther 利用方針の見直し

## 解決したい課題

現在のEmtherは、機能としては一定揃っている一方で、以下の課題がある。

* EM自身が情報を入力・整理するコストが大きい
* AIからのアウトプットが多く、確認・判断するコストが発生している
* AIの思考や分析過程を見せることで、さらに情報量が増えている
* 機微情報・個人情報・機密情報を扱う場合のリスクが高い
* 結果として、EMの業務を楽にするためのシステムが、Emtherを利用するための業務を生み出している

そのため、機能を増やすことよりも、**EMとEmtherの役割分担・情報の扱い方・アウトプットの見せ方を見直す。**

## 基本コンセプト

> **EMは「記録する人」ではなく「考え、判断する人」。
> AIは「答えを出す人」ではなく「思い出させ、整理し、注意を向ける人」。**

EMの認知や判断を支援しながら、Emtherを使うための負担は最小限にする。

## 方針

### 1. Journalの使い方を見直す

Journalをイベントごとの記録として扱わず、**EM自身の振り返り・思考を残す場所**として位置づける。

日々の出来事を逐一入力することを求めず、AIによる問いかけなどを通じて、EMが1日を振り返りながら必要なことを記録できるようにする。

### 2. AIのアウトプットを絞る

AIが発見した情報や提案を大量に並べるのではなく、**EMが注意を向けるべき重要なものと、それ以外を明確に分ける。**

AIの分析能力を高めること以上に、EMが確認・判断する情報量を抑えることを重視する。

### 3. AIの思考過程は原則として隠す

AIの思考や分析過程を常に表示するのではなく、**基本は判断・結論を中心に提示し、必要な場合だけ根拠や詳細を確認できる**形とする。

情報の透明性と情報量のバランスを取り、EMの認知負荷を抑える。

### 4. 機微情報は「詳細を蓄積しない」方向へ

MCP等による情報収集を単純に行うのではなく、**機微情報を含む生データをそのままEmtherや外部AIに渡さない**ことを基本とする。

必要に応じてローカル環境などで情報を処理し、Emtherには詳細な内容ではなく、EMが判断するために必要な最小限の状態・変化・シグナルのみを扱う。

## 目指す状態

Emtherを利用することで、

> **EMが情報を記録・整理・確認する時間を増やすのではなく、EMが考え、判断するための時間と認知的な余白を増やす。**

そのために、
**「入力を減らす」「見るものを減らす」「必要な情報だけを残す」**
ことを基本的な設計思想とする。
