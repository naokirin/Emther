## 0. 課題認識（再確認後）

**関心を上げるための部品（戦略・人・閉ループ・時系列・冷スタート）は揃った。**  
一方で、ダッシュボードを使う側のストーリー——特に「判断と雑務の分離」「AIが生成する仕事の編集権」——はまだ弱い。人間EMが迷子になり、生成されたやることに忙殺されるリスクは残っている。タブと機能が増えた分、**迷子要因は以前よりむしろ増えうる。**

| 以前（A〜G直後）の整理 | いま |
|---|---|
| 短い日常ループはあるが、戦略・人・閉ループが無い | A〜O で中期ギャップの部品も実装済み |
| 最優先はキュー再編集＋関心上げの両方 | **最優先はキュー再編集（P0）とナビ／物語の再編**。関心上げは「あるが日常に編入しきれていない」 |

一言で言うと:

- いまのUXは「Runに応答し、組織の前提・人・履歴も見られるコックピット」まで来た
- 目指すUXは「今日向き合う組織の問いを選び、介入し、変化を読む人」を中心に据えること
- **部品追加より、判断キューの編集と画面の主問の明確化が先**

## 1. このプロダクトが想定する人間EMの役割

ビジョン（`em_v5.md`）:

> EMの関心を現場の効率化から、組織設計とミッションの実現へと引き上げる

人間EMが担うべき仕事は次の4層である。

| 層 | EMの仕事 | システムの役割（現状） |
|---|---|---|
| **憲法** | MVV・体制・制約・目標を決める | `/org`（Strategy／Teams／Objectives）、初回セットアップバナー |
| **感知** | 現場の揺らぎを事実として残す | Dashboard Quick Journal（直近）＋ `/journal`（全件検索） |
| **判断** | 何を課題にし、何を捨て、いつ介入するか | Inbox／「次にすべきこと」／`/chat`／Yield |
| **介入** | 人・仕組み・優先順位を動かし、結果を見る | Issue Workspace（型・KR/チーム紐付け・分解・介入効果） |
| **振り返り** | 組織と自分の変化を読む | `/timeline`／`/reports`／`/growth`／People |

AIは選択肢と壁打ち相手。最終決断と説明責任は人間EM。ここがブレると「AIのやることに忙殺されるツール」になる。

### 現状の画面構成（参照）

TopNav は実質 **約10画面**（A〜G時点の5画面から大幅増）。

| Route | 画面 | 主な役割 |
|---|---|---|
| `/` | Dashboard | 初回セットアップ、時間帯バナー、次にすべきこと、Fleet、Activity、Vitals、Quick Journal（直近5件）、Inbox |
| `/journal` | Journal | 全件の横断検索・絞り込み・校正（P） |
| `/chat` | 何でも相談 | Issue未紐付けの壁打ち、Issue化／様子見／却下 |
| `/issues`・`/issues/[id]` | Issue Workspace | 介入の計画・実行・Yield・壁打ち・KR/チーム紐付け・子Issue分解・介入効果 |
| `/people`・`/people/[id]` | People | 人軸でプロファイル・Journal・Issueを横断（J） |
| `/timeline` | Timeline | 組織の変更履歴を日付で読む（N） |
| `/reports` | Reports | 週次/月次の観測スナップショット＋所感（Q） |
| `/growth` | EMの成長 | 自己チェックイン・KPT・改善方針（R） |
| `/org` | Organization Context | 憲法（Strategy／Teams＋charter／Objectives） |
| `/settings` | Settings | 閾値・自動起動・フォールバック等 |

## 2. 人間EM側のストーリー（あるべき日常）

ストーリー自体は変わらない。変わったのは「どの画面がその線を支えられるか」である。

### ストーリーA：朝のトリアージ（「何が起きているか」）

1. Dashboardを開く
2. **組織の状態**（Vitals／評価不能）を数秒で掴む
3. **自分の判断が必要なものだけ**を優先度付きで見る
4. 1件ずつ「今やる／様子見／捨てる」を決める
5. （任意）`/timeline` や `/reports` で昨日からの差分を眺める

成功条件: 「今日EMとして向き合う組織課題」が3〜5件に絞られる。

### ストーリーB：日中の感知（「事実を溜める」）

1. 1on1・会議のあと Quick Journal に投げる
2. 抽出を校正し、組織の事実にする
3. 必要なものだけ相談やIssueへ昇格
4. 横断検索・振り返りは `/journal` へ

成功条件: Journalが「メモ箱」で終わらず、翌朝のトリアージ材料になる。

### ストーリーC：モヤモヤの昇格（「追跡する／しない」）

```
モヤモヤ     → 何でも相談 → Issue化 / 様子見 / 却下
自動検知     → 相談で確認 → 同上
決まった介入 → Issue Workspaceのみ
```

成功条件: 「相談」と「介入」の境界が迷わず、Issueが実装タスク箱にならない。

### ストーリーD：介入の実行（「仕組みを動かす」）

1. Why/What/How・介入の型・関連チーム・Key Result を固める
2. Yieldで選択肢を選ぶ／情報を足す
3. Action Items／子Issue分解を育てる（AI提案は採用まで本体不変）

成功条件: EMは「決める人」であり、Runの監視人ではない。

### ストーリーE：振り返りと学習（「組織が変わったか」）

1. アーカイブ後に「介入の効果」で前後比較を見る（L）
2. `/timeline`・`/reports`・People で変化を読む
3. 続ける／ピボット／閉じるを決める
4. （任意）`/growth` で自分自身の方針も振り返る

成功条件: 完了チェックではなく、組織変化で判断できる。

### ストーリーF：期初・冷スタート（「前提を置く」）

Dashboardの初回セットアップバナーに従い、MVV・Team・Objectiveを揃えてからエージェントを本格稼働させる（O）。

## 3. 意図された接点と、AIがEMの仕事を増やす経路

### 3.1 設計上の日常接点

| 時間帯 | EMの行動 | システム上のUX |
|---|---|---|
| 朝 | 全体把握・計画確認 | Dashboard／Vitals／次にすべきこと／Yield、必要なら Timeline・Reports |
| 日中 | 1on1、会議、トラブル対応 | Quick Journal → `/journal` |
| 適時 | 方針策定・Issue解決 | Issue Workspace／People／何でも相談 |
| 期初/適時 | 前提条件の更新 | Organization Context（セットアップバナー誘導） |
| 週次/月次 | 振り返り | Reports／EMの成長 |

### 3.2 EMに仕事を発生させる機能（現状）

1. Yield（選択肢待ち／情報不足）
2. 自動異常検知（Journal urgency=high → Lead Run）
3. 朝サマリー（バッチ Lead Run）
4. 要注目 Journal（mid＋negative、24h）
5. Team Vitals / 1on1 Coverage（warn/bad／評価不能）
6. Charter未整理 Issue
7. 実行異常（error／無応答）
8. 手動エージェント起動
9. Lead → 専門エージェント **並列** consult（子 Run が同時に増える・M）
10. AI提案 Action Items／**子Issue分解** の採用／却下（K）
11. 長期プロファイル下書き（記録まで未保存）
12. （間接）Reports／Growth／Timeline——生成物ではないが、**見るべき画面の選択肢**が増える

生成・提示の抑制と束ねが弱いと、オペレーションキュー化する。M/K でAIの提案力は上がったが、**キュー側の編集権は追いついていない。**

## 4. 現状とのズレ：なぜ迷子・忙殺になりやすいか

### 実装済みになったもの（以前のギャップ → 現状）

| 以前の指摘 | 現状 |
|---|---|
| (5) ミッションへの一本線がない（H） | Objective/KR 構造化、Issue の `keyResultId`、進捗自動算出、Runtime注入まで実装済み |
| (6) 人軸の物語がない（J） | `/people` ハブ実装済み（directory・Journal・Issueを横断） |
| (7) 閉ループがない（L） | アーカイブ＋チーム紐付き Issue に「介入の効果」パネル |
| 冷スタート（O） | Dashboard 上部に初回セットアップバナー |
| 時系列（N） | `/timeline` |
| チーム憲法（I） | `Team.charter`、Issue `teamId`、関連チームのみ憲法を動的注入 |
| 協働計画の深さ（K） | `sub_issues` 提案＋採用/却下 |
| AIチーム協働（M） | Lead の並列 consult |

これらは「関心上げ」の線を支える部品としては揃った。ただし **朝のトリアージや「次にすべきこと」からは、戦略・人・効果・差分がまだ主役になっていない。** あるが編入されていない、という段階である。

### いまも残る／むしろ強まったズレ

#### (1) 「次にすべきこと」が組織課題ではなくオペレーションキューになりやすい【未解消・P0】

現状も1本のリストに次が並ぶ（上限6件＋「他N件」）:

- Yield / エラー / 無応答
- 未確認の自動検知・朝サマリー
- Charter未整理 Issue
- Vitals warn/bad・評価不能
- 要注目 Journal

種別チップはあるが、**判断待ち / 観測不足 / 整備**のレーン分離はない。並列 consult（M）や子Issue提案（K）で Run・提案が増えるほど、本当の判断待ちが押し出されやすい。

#### (2) Inboxクリック＝即Issue化が境界を壊す【未解消・P0】

自動起動は `/chat` で確認できるが、手動 Run や Inbox 行クリックは `goToRunIssue` で**即Issue化**のまま。ストーリーCと衝突する。

#### (3) 「様子見」に回収ストーリーがない【未解消・P0】

`watching` は緊急度から外れるが、ウォッチリスト・期限・再浮上はない。

#### (4) Dashboardが情報過多で「最初の一文」が弱い【未解消・悪化しうる】

初回セットアップ＋時間帯バナー＋次にすべきこと＋Fleet＋Activity＋Vitals＋Journal＋Inboxが同居。Journal全件は `/journal` に分離されたが、**主問の圧縮（「今日の組織の問い」）は未着手。**

#### (5') 戦略線はあるが朝の物語に乗っていない【部品済み・編入不足】

Objective/KR↔Issue はあるが、Dashboard先頭や「次にすべきこと」が「今期のために何を解いているか」を語らない。進捗は `/org` 側に寄りがち。

#### (6') Peopleハブはあるがトリアージと弱い【部品済み・編入不足】

`/people` はあるが、要注目人物・評価不能メンバー・様子見中の相談が朝キューに人軸で出てこない。

#### (7') 閉ループはあるが「終わったあと」限定【部品済み・編入不足】

介入効果はアーカイブ後のみ。進行中介入の「観測できているか」は朝のキューと繋がっていない。

#### (8) AIが仕事を増やす方向に偏っている【未解消・M/Kで増幅】

自動検知・朝サマリー・並列consult・Action Items・子Issue・要注目Journal——いずれも入力待ちを増やせる。束ね・上限・却下コスト低減は弱い。

#### (9) ナビ過多による迷子【新規】

約10タブ。感知／相談／介入／憲法／振り返りの物語がナビラベルだけでは伝わらない。「今どの物語にいるか」の一文ガイドも未実装（旧P1-6）。

#### (10) ローカルNER誤検出が体験を壊しうる【既知・memo TODO】

自由記述の一般語・チーム名・テンプレ語が人物名として誤登録され、最悪は Agent Run 送信全体が止まる。EMに確認・削除UIが無い。忙殺とは別系統だが、**信頼と継続利用を直接脅かす。**

### その他の摩擦（補足）

- Fleet は種別ごとの「最新1本」信号機のまま（並列時は Activity／Inbox で補完）
- Journal 抽出品質のばらつき、校正UIはあるが自動検知は校正必須ではない
- 名前一致依存の関連付けは表記ゆれに弱い（PeopleハブのIssue関連も簡易抽出）
- 全チーム名簿の Runtime 注入は、紐づく Issue の teamId またはタスク本文中のチーム名言及があれば関連チームへ絞り込み（P2-13対応）。手がかりが無い場合のみ全件注入にフォールバック
- Journal／Reports／Growth の画面側マスキングは未実装（LLM送信前マスクは済み）

| A〜G | 線を通す（見つけ→相談→課題化→観測） | **完了** |

| **本整理の P0〜P1** | 線の上で迷子・忙殺しない／部品を日常物語に編入する | **いまここ（未着手〜部分）** |
| P2 | 信頼（NER）と残基盤 | memo TODO 中心 |

以前の文書は「P0のあとでH〜O」と書いていたが、実装順序としては **H〜Oが先に入った。**  
そのため現在の課題は「関心上げ部品が無い」ではなく、**関心上げ部品があるのに、朝の判断体験がまだオペレーションキューのまま**であること。

## 7. 進め方の提案

1. **まず P0（1〜5）**: 既存 Dashboard／Inbox／chat の導線再編集。新画面は増やさない
2. **並行または直後に P1-6・11**: ナビの物語ラベル／週次画面の位置づけ（タブ増への対処）
3. **P1-7〜10**: H/J/L を朝の要約に薄く載せる（一覧のポートフォリオ化含む）
4. **P2-12（NER）**: 体験破壊の既知バグとして優先度を別枠で高く扱う
5. その他 P2 は基盤・秘匿・深化として随時
